# 디자인 원칙

Cozy 화면이 따르는 원칙이다(ADR-0031). Tabler가 구현을, Shopify Polaris가 원칙을, AWS Cloudscape가 만들기·상세·수정·삭제 흐름을 맡는다. 원칙은 컴포넌트에 들어 있다. 앱은 컴포넌트를 조합하고, 어기면 빌드 규칙(R14, R15)이나 화면 확인(runtime-verifier V9~V11)에서 걸린다.

## 1. 흐름: 왼쪽 위에서 오른쪽 아래로

시선과 조작은 왼쪽 위에서 시작해 오른쪽 아래에서 끝난다. 주 동작은 그 끝자리에 둔다.

| 자리 | 무엇 | 예 |
| --- | --- | --- |
| 왼쪽 위 | 경로와 화면 제목 | 메모 › 회의록 정리 |
| 오른쪽 위 | 화면 전체에 대한 동작. 주 버튼이 맨 오른쪽 | [메모 만들기], [삭제] [수정] |
| 본문 | 위에서 아래로 읽는 내용 | 필터 → 표 → 페이지 이동 |
| 오른쪽 아래 | 폼의 끝. [취소] [주 버튼] | [취소] [메모 만들기] |

- **주 버튼**: 버튼 묶음 하나에 주 버튼(`btn-primary`)은 하나다. 묶음의 맨 오른쪽(마지막)에 둔다(R15). 표 안에는 주 버튼을 두지 않는다.
- **되돌릴 수 없는 동작(삭제)**: 주 자리에 두지 않는다. 머리의 보조 버튼(critical 글자)으로 두고 확인 창을 거친다.

## 2. 화면 유형과 폭

본문은 Tabler 12칸 그리드 위에서 가운데 정렬한다. 화면 유형마다 폭을 정한다.

| 화면 | 패턴 | 폭 | 구성 |
| --- | --- | --- | --- |
| 목록 | `list-with-filter` | `container-xl` | 오른쪽 위 만들기 · 카드: 필터 → 표 → 전체 건수와 페이지 이동 |
| 만들기 | `form-page` | 가운데 48rem | 경로 · `<form class="card">`: 입력 칸 → 오른쪽 아래 [취소] [대상 만들기] |
| 상세 | `details` | `container-xl` | 경로 · 오른쪽 위 [삭제] [수정] · 본문(넓은 칸 8) + 속성(옆 칸 4, `datagrid`) |
| 수정 | `form-page` | 가운데 48rem | 경로(대상 이름 › 대상 수정) · 만들기와 같은 칸 → [취소] [저장] |
| 개요 | `overview` | `container-xl` | 숫자 카드 줄 → 카드들 |
| 목록 + 상세 | `master-detail` | `container-xl` | 왼쪽 목록 4 + 오른쪽 상세 8 |

- **워크벤치 전용 유형**: 워크벤치의 화면 보기는 전체 너비 3단 구성이다(ADR-0038). 앱 화면에는 쓰지 않는다.

  | 화면 | 폭 | 구성 |
  | --- | --- | --- |
  | 워크벤치 화면 보기 | 전체 너비(`container-fluid`) | 머리 한 줄(워드마크, 메뉴, 검색 칸) · 왼쪽 18rem(화면 목록, 구조 트리) + 가운데(미리보기나 소스) + 오른쪽 21rem(속성이나 샘플 데이터) |
  | 워크벤치 개요 | 전체 너비(`container-fluid`) | 같은 머리 · 숫자 카드 줄 → 넓은 칸 7(화면 목록) + 옆 칸 5(규칙 위반, 모듈, 미구현 항목). 앱의 개요(`overview`)와 같은 순서다 |
  | 워크벤치 검색 | 가운데 칸 56rem | 같은 머리(검색 칸은 화면 안으로) · 검색 칸 → 묶음마다 카드 하나의 결과 목록 |

  - 세 칸이 화면 높이를 채우고 칸마다 따로 스크롤한다. 1200px보다 좁으면 가운데, 왼쪽, 오른쪽 순서로 한 열에 쌓인다.
  - 밀도가 높다. 목록과 표의 줄 간격을 앱 화면보다 좁게 쓴다. 글자 크기(12px 이상)와 대비(§4)는 앱 화면과 같다.
  - 속성은 왼쪽 열이 항목 이름인 표로 보인다.

## 3. 만들기 · 상세 · 수정 · 삭제

| 동작 | 화면과 흐름 | 끝나면 |
| --- | --- | --- |
| 만들기 | `GET /메모/new` → `POST /메모`. 제목과 버튼은 "메모 만들기" | 상세로 이동, 플래시 "메모를 만들었습니다" |
| 상세 | `GET /메모/{id}`. 읽기 전용 | — |
| 수정 | `GET /메모/{id}/edit` → `POST /메모/{id}`. 버튼은 "저장" | 상세로 이동, 플래시 "메모를 수정했습니다". 바뀐 게 없으면 저장하지 않고 "바뀐 내용이 없습니다"(info) |
| 삭제 | 상세 머리의 [삭제] → 확인 창 → `POST /메모/{id}/delete` | 목록으로 이동, 플래시 "메모를 삭제했습니다" |

- **확인 창(`delete-confirm`)**: 제목은 "메모 삭제"다. 본문은 "지울 메모: **회의록 정리**"와 "지우면 되돌릴 수 없습니다."이고, 버튼은 [취소] [삭제]다.
- **검증**:
  - 입력하는 중에는 오류를 띄우지 않는다.
  - 제출하면 서버가 칸 아래에 오류를 보이고, 첫 오류 칸으로 포커스가 간다.
  - 칸과 상관없는 서버 오류는 버튼 위 `alert('critical', …)`로 보인다.
  - 주 버튼은 비활성화하지 않는다.
- **저장하지 않은 입력**: 만들기·수정 화면에서 입력을 바꾼 뒤 떠나려 하면 브라우저가 확인한다(cozy.js).
- **비어 있을 때**: 두 경우를 구분한다.
  - 아직 아무것도 없다: `emptyStateAction`. 무엇을 만들 수 있는지 알리고 [대상 만들기] 버튼을 둔다.
  - 조건에 맞는 것이 없다: `noResults(조건 없는 목록 주소)`. [조건 지우기] 버튼을 둔다.

## 4. 색

색은 의미에만 쓴다. 글자 대비는 4.5:1 이상, 아이콘과 경계선은 3:1 이상이다(WCAG 2.2 AA).

| 역할 | 색 | 쓰는 곳 |
| --- | --- | --- |
| 중립 | 흰색·회색 | 화면 대부분. 본문 글자, 카드, 보조 글자(`text-secondary`, 5.5:1) |
| 조작 | 파랑(primary) | 주 버튼, 링크, 현재 메뉴, 현재 페이지 번호, 포커스 |
| tone | 아래 표 | 상태와 알림만 |

| tone | 뜻 | 글자 / 바탕 | 대비 |
| --- | --- | --- | --- |
| `neutral` | 분류, 보조 정보 (예: 고정) | `#3f3f46` / `#f0f0f2` | 9.2:1 |
| `info` | 알림, 진행 중, 바뀐 내용 없음 | `#0a4f94` / `#e6f0fa` | 7.1:1 |
| `success` | 완료, 정상 | `#1d6b30` / `#e7f5ea` | 5.8:1 |
| `warning` | 주의, 미완료 | `#7a4300` / `#fdf1dc` | 7.1:1 |
| `critical` | 오류, 할 수 없음, 되돌릴 수 없는 동작 | `#a51d1d` / `#fbe9e9` | 6.4:1 |

- **분류는 색으로 나누지 않는다**: 종류가 다른 것은 neutral 배지의 글자로 구분한다.
- **색만으로 뜻을 전하지 않는다**: 알림에는 아이콘이, 상태 배지에는 글자가 붙는다.
- **앱 화면은 색 클래스를 직접 쓰지 않는다(R14)**:
  - 색은 tone을 받는 컴포넌트가 고른다: `badge('고정', 'neutral')`, `alert('critical', …)`, `deleteConfirm(…)`.
  - 앱에 허용하는 것은 `text-secondary`, `text-muted`, `btn-primary`뿐이다.
- **숫자 카드(`stat`)와 활동 아이콘**: 색 없이 중립으로 둔다.
- **토큰**: `cozy.css`의 `--cozy-{tone}-fg`, `--cozy-{tone}-bg`. Tabler 기본값이 미달인 곳(보조 회색, 알림 글자, 위험 버튼)도 여기서 바로잡는다.

## 5. 글자와 간격

- **글꼴**: Pretendard. 숫자와 날짜는 자릿수를 맞춘다(`tabular-nums`).
- **글자 단계** (Tabler 값):

  | 용도 | 크기 | 요소 |
  | --- | --- | --- |
  | 화면 제목 | 20px | `.page-title` (화면에서 가장 큰 글자) |
  | 카드 제목 | 16px | `.card-title` |
  | 본문, 입력, 버튼 | 14px | |
  | 보조(표 머리, 시각, 설명) | 12~14px, `text-secondary` | 12px보다 작게 쓰지 않는다 |

- **위계**: 굵기와 크기로 나눈다. 색만으로 위계를 만들지 않는다. 한글은 단어 중간에서 줄을 바꾸지 않는다(빈 상태, 알림은 `keep-all`).
- **간격** (4px 단위, Tabler 단계):

  | 간격 | 값 |
  | --- | --- |
  | 버튼 사이 | 8px (`btn-list`) |
  | 입력 칸 사이 | 16px (`mb-3`) |
  | 카드 안쪽 | 20px |
  | 카드 사이 | 16px (`row-cards`) |
  | 제목줄과 본문 사이 | Tabler `page-body` 기본 |

- **밀도**: 보통 하나만 둔다. 한 화면 안에서 밀도를 섞지 않는다.

## 6. 문구

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 버튼 | 대상 + 동사. 수정 폼의 주 버튼은 "저장" | 메모 만들기, 저장, 삭제, 조건 지우기 |
| 화면 제목 | 목록은 대상, 만들기·수정은 "대상 + 동사", 상세는 대상 이름 | 메모 / 메모 만들기 / 회의록 정리 |
| 결과 알림 | 대상을 + 과거형 | 메모를 만들었습니다, 메모를 삭제했습니다 |
| 빈 상태 | 무엇이 없는지 + 다음에 할 일 | 메모가 없습니다. 첫 메모를 만들어 보세요. |
| 오류 | 무엇을 하면 되는지 | 제목을 입력하세요 |

## 7. 피드백 종류

| 종류 | 언제 | 컴포넌트 |
| --- | --- | --- |
| 플래시 | 만들기·수정·삭제의 결과. 리다이렉트 뒤 page-body 맨 위 | `CozyFlash.success/info/warning/critical` |
| 칸 오류 | 검증 오류. 칸 바로 아래 | `field` |
| 알림 | 화면에 머무는 안내나 칸과 무관한 오류 | `alert(tone, 문장)` |
| 토스트 | 사소한 확인(복사), 연결 오류. 중립 바탕, critical만 빨강 | `Cozy.toast`, `toast(kind, 문장)` |
| 확인 창 | 되돌릴 수 없는 동작 앞 | `deleteConfirm` |
| 진행 표시 | 요청 중. 화면 맨 위 막대, 검색 칸 오른쪽 스피너 | 자동, `loading()` |
