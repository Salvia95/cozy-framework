# 워크벤치 (cozy-workbench)

앱을 dev로 실행하면 `/cozy/dev/workbench`에서 화면의 구조, 상태별 미리보기, 소스를 본다. 결정은 [ADR-0036](../adr/0036-workbench.md)과 [ADR-0038](../adr/0038-workbench-redesign.md)(용어, 디자인 개선)에 있다. 워크벤치는 dev 전용 도구이고 배포 패키지에는 들어가지 않는다.

- **지금 되는 것**: 모듈별 화면 목록, 화면의 구조 트리(패턴 → 영역 → 프래그먼트, 접고 펴기), 선택한 항목의 속성, 상태와 화면 너비 전환, 좌우 칸 접기, 템플릿과 화면 명세 소스 보기, 요소를 눌러 소스 위치 찾기, 에이전트용 글 복사, 검사 결과와 수정 명령, 모듈 의존성 다이어그램과 표, 폼으로 cozy 명령 실행(변경 파일 확인 → 적용), 샘플 데이터 수정(객체는 속성 표, 목록은 그리드, 타입에 맞는 입력)과 상태 복제
- **하지 않는 것**: 자유 배치, 색·간격 편집, HTML 편집, 스펙에 키나 목록 항목을 더하고 빼기

## 용어

워크벤치 화면은 아래 용어를 쓴다. 한 개념에 용어 하나다. `WorkbenchTermsTest`가 메뉴, 상태 이름, 구조 트리, 생성 항목 목록을 확인한다.

- **표기**: 사람이 읽는 이름을 앞에, 식별자를 뒤에 고정폭 회색 글자로 쓴다(`페이지네이션 pagination`). 식별자는 지우지 않는다.
- **낱말**: 동작은 일반 UI 용어(추가, 삭제, 저장, 적용, 확인, 검색, 복사)를, 개발 용어는 통용 표기(프래그먼트, 컴포넌트, DTO, 이벤트 리스너)를 쓴다. 새 조어를 만들지 않는다.
- **에이전트용 글**은 식별자로 쓴다(`Inside: list-with-filter (패턴) > …`).
- **cozy 명령의 메시지**(레시피 설명, 고치는 법, 다음 할 일)는 명령이 낸 그대로 보인다. 이 용어집의 대상이 아니다.

| 용어 | 뜻 | 예전 표기 |
| --- | --- | --- |
| 화면 | 화면 스펙이 있는 템플릿 하나 | |
| 모듈 | 모듈의 의존성, 공개 API, 이벤트, 화면 (메뉴) | 지도 |
| 코드 생성 | cozy 명령을 폼으로 실행하는 화면 (메뉴) | 만들기 |
| 검사 | `cozy check`의 결과 (메뉴) | |
| 컴포넌트 | 패턴 카탈로그 (메뉴) | 패턴 카탈로그 |
| 샘플 데이터 | 화면 스펙의 상태에 든 값 | 값 |
| 화면 명세 | 화면 스펙 파일 `specs/*.yml` | 스펙 |
| 영역 | 패턴이 fragment로 받는 부분 (`필터 영역`) | 자리 |
| 프래그먼트 | `th:fragment` 선언과 그 삽입 | fragment 선언 |
| 생성 항목 | 레시피 하나 | 레시피 |
| 입력 항목 | 레시피의 인자 | 인자 |
| 변경 파일 확인 | `--dry-run`으로 바뀔 파일을 보는 일 | 계획 보기 |
| 생성 · 수정 · 삭제 · 변경 없음 | 변경 파일의 구분 | 만듦 · 바꿈 · 지움 · 그대로 |
| 미구현 항목 | 명령이 남긴 `cozy:slot` | 빈칸 |
| 수동 수정 항목 | 명령이 위치를 찾지 못해 사람이 고칠 곳 | 손으로 할 일 |
| 의존 모듈 | `allowedDependencies`의 모듈 | 의존 |
| 참조하는 모듈 | 이 모듈에 의존하는 모듈 | |
| 명령 인터페이스 · 조회 인터페이스 | `*Facade` · `*Finder` | 쓰기 · 읽기 |
| DTO | `spi/dto`의 record | 값 |
| 발행 위치 | 이벤트를 발행하는 파일 | 발행하는 곳 |
| 요소 선택 · 경로 복사 | 미리보기에서 요소를 선택하고 `파일:줄`을 복사 | 요소 고르기 · 위치 복사 |
| 화면 너비 | 미리보기의 폭 | 폭 |
| 속성 | 선택한 화면이나 구조 항목의 정보를 보이는 표 | |
| 매개변수 | 프래그먼트 호출에 넘긴 인자 | |

- **상태 이름**: 관례 이름은 표시 이름으로 보이고 식별자는 버튼의 `title`에 남는다. 그 밖의 이름은 식별자 그대로다.

  | 식별자 | 표시 이름 |
  | --- | --- |
  | `default` | 기본 |
  | `empty` | 데이터 없음 |
  | `noResults` | 검색 결과 없음 |
  | `paged` | 여러 페이지 |
  | `invalid` | 입력 오류 |

- **컴포넌트 이름**: 매니페스트의 `label`이다([ui.md](ui.md)). 프레임워크 항목은 KRDS에 같은 역할의 컴포넌트나 기본 패턴이 있으면 그 명칭을 쓴다. `label`이 없으면 종류(컴포넌트, 프래그먼트, 영역)와 식별자로 표시된다.
- **생성 항목 이름**: `cozy recipes --json`의 `title`과 `group`이다([cli.md](cli.md)).
- **규칙 이름**: 검사 화면은 규칙 ID 앞에 이름을 붙인다(`다른 모듈 템플릿 참조` `오류 R3`). 이름은 `cozy-rules`의 `RuleNames`에 있다.
- **워드마크**: 머리의 "Cozy Workbench"는 Courgette(SIL OFL 1.1)의 글자를 SVG 경로로 바꾼 것이다. 글꼴 파일은 없다. 글자색(`currentColor`)을 따른다.

## 넣기

- 새 앱: 아키타입이 `pom.xml`에 `cozy-workbench`를 넣는다.
- 이미 있는 앱: `cozy enable workbench`. `cozy-ui` 블록 바로 뒤에 넣는다. cozy-parent가 1.2.0보다 낮으면 실패한다.

```xml
<dependency>
  <groupId>io.salvia95.cozy</groupId>
  <artifactId>cozy-workbench</artifactId>
</dependency>
```

- 앱 코드는 이 모듈의 타입을 쓰지 않는다. 자동 설정만 쓴다.
- **배포 패키지**: `cozy-parent`가 실행 jar에서 `cozy-workbench`, `cozy-cli`, `cozy-rules`를 뺀다. 제3자 라이선스 목록에도 없다.

## 켜지는 조건

| 속성 | 기본값 | 뜻 |
| --- | --- | --- |
| `cozy.dev.workbench.enabled` | dev 프로필이면 `true`, 아니면 `false` | `/cozy/dev/workbench` 등록 |
| `cozy.dev.workbench.project-dir` | 없음 | 앱 프로젝트 폴더를 직접 정한다. 위로 올라가며 찾지 않고 이 폴더만 본다 |

- 패턴 카탈로그(`cozy.dev.catalog.enabled`)가 켜져 있어야 한다. 매니페스트와 화면 미리보기(`/cozy/dev/catalog/screen`)를 카탈로그가 준다.
- **앱 프로젝트 폴더에서 실행해야 구조와 소스가 보인다.** 실행한 폴더에서 위로 올라가며 `pom.xml`과 `src/main/java`가 있는 폴더를 찾는다. 못 찾으면(jar나 app-image로 실행) 미리보기만 보이고 화면이 이유를 알린다.
- dev 실행에는 JDK가 필요하다(cozy-cli가 javac 파서를 쓴다).

## 주소

고른 것은 모두 주소의 파라미터에 있다. 주소를 그대로 주고받을 수 있다.

| 파라미터 | 값 | 기본 |
| --- | --- | --- |
| `spec` | 화면 스펙 이름 (`memo-list`) | 첫 화면 |
| `state` | 스펙의 상태 이름 | 스펙의 첫 상태 |
| `w` | 미리보기 폭: `full`, `1024`, `768`, `390` | `full` |
| `view` | `preview`, `template`, `spec`(화면 명세)은 가운데 칸에 보일 것. `fixture`는 미리보기 옆 오른쪽 칸에 샘플 데이터 | `preview` |

- 없는 `spec`이나 `state`는 404, 목록에 없는 `w`나 `view`는 400이다.
- 소스 보기(`view=template`, `view=spec`)의 줄마다 `id="L{줄}"`이 있다.

## 화면 보기의 구성

화면 보기(`/cozy/dev/workbench`)는 세 칸이다. 세 칸이 화면 높이를 채우고 칸마다 따로 스크롤한다. 1200px보다 좁으면 한 열로 쌓인다([design.md](design.md) §2).

| 칸 | 내용 |
| --- | --- |
| 왼쪽 | 화면 목록(모듈별로 묶고, 화면 명세의 `title`과 식별자로 보인다. `title`이 없으면 식별자만)과 선택한 화면의 구조 트리 |
| 가운데 | 탭 `미리보기 · 템플릿 · 화면 명세`. 미리보기에는 상태, 화면 너비, 요소 선택 스위치가 있다 |
| 오른쪽 | 탭 `속성 · 샘플 데이터`. 샘플 데이터를 고치는 동안 미리보기가 가운데에 그대로 보인다 |

- **머리**: 워드마크와 메뉴가 한 줄이다. 모든 워크벤치 화면이 같은 머리를 쓴다.
- **칸 접기**: 가운데 칸 머리의 버튼 두 개로 왼쪽 칸과 오른쪽 칸을 접는다. 둘 다 접으면 미리보기가 전체 너비를 쓴다. 접은 상태는 브라우저에 남아(`localStorage`의 `cozy.workbench.fold.side`, `cozy.workbench.fold.inspector`) 화면을 옮겨도 유지된다. 주소에는 넣지 않는다.
- **속성**: 왼쪽 열이 항목 이름인 표다. 아무것도 선택하지 않으면 화면의 속성(이름, 식별자, 모듈, 템플릿, 화면 명세, 상태, 규칙 위반)이 보인다. 구조의 줄이나 미리보기의 요소를 선택하면 그 항목의 속성으로 바뀐다.

  | 구획 | 항목 |
  | --- | --- |
  | 기본 정보 | 이름, 종류, 식별자(매니페스트의 id), 설명(매니페스트의 `purpose`), 상위 경로, 소스 위치(`파일:시작–끝`), 템플릿(삽입한 템플릿) |
  | 매개변수 | 삽입에 넘긴 인자. 이름은 매니페스트 파라미터의 `label`(없으면 파라미터 이름), 값은 템플릿에 적힌 그대로다 |

  - 다른 템플릿이 그린 요소를 선택하면 "렌더링한 템플릿" 행이 붙는다.
  - 속성은 읽기 전용이다. 매개변수 수정은 뒤 단계에서 넣는다(ADR-0038 §7).

## 화면 넷

| 주소 | 보이는 것 | 원본 |
| --- | --- | --- |
| `/cozy/dev/workbench` | 화면: 구조, 미리보기, 소스 | `cozy describe --json`, 패턴 카탈로그의 미리보기 |
| `/cozy/dev/workbench/check` | 검사: 파일마다 위반, 고치는 법, 고치는 명령 | `cozy check --json` |
| `/cozy/dev/workbench/commands` | 코드 생성: 생성 항목마다 폼, 변경 파일 확인, 적용 | `cozy recipes --json`, `cozy add·link·enable … --json` |
| `/cozy/dev/workbench/map` | 모듈: 의존성 다이어그램이나 표, 선택한 모듈의 속성(의존 모듈·참조하는 모듈·공개 API·이벤트·이벤트 리스너·화면), 미구현 항목 | `cozy describe --json` |

- **검사**: 위반의 문구와 고치는 명령은 `cozy check`가 내는 것과 같다. 명령 옆의 "복사"로 클립보드에 넣는다. 워크벤치가 명령을 실행하지는 않는다.
  - 화면 템플릿이나 스펙의 위반은 줄 번호가 워크벤치의 소스 보기 그 줄로 이어진다.
  - 화면 목록에는 화면마다 위반 수가, 머리의 "검사"에는 전체 오류 수가 붙는다.
  - 검사하지 못하면(`cozy check`의 종료 코드 2) 이유를 그대로 보인다.
- **프레임워크 템플릿**: 워크벤치는 실행 중인 cozy-ui의 jar나 클래스 폴더를 cozy 명령에 `--ui`로 넘긴다. Maven 저장소를 찾지 않고, 앱이 지금 쓰는 프레임워크 템플릿으로 검사한다.
- **모듈**: 아래 "모듈 화면"에 적었다. 화면은 워크벤치의 그 화면으로 이어진다. 미구현 항목은 `파일:줄`과 채울 내용으로 보인다.

## 모듈 화면

`/cozy/dev/workbench/map`은 왼쪽에 모듈 의존성, 오른쪽에 속성을 보인다. 원본은 `cozy describe --json` 하나다.

| 파라미터 | 값 | 기본 |
| --- | --- | --- |
| `module` | 선택한 모듈 이름 | 없음 (앱의 속성이 보인다) |
| `view` | `diagram`(다이어그램), `table`(표) | `diagram` |

- 없는 `module`은 404, 목록에 없는 `view`는 400이다.
- **다이어그램**: 서버가 좌표를 계산해(`ModuleGraph`) SVG로 그린다. 스크립트와 외부 라이브러리가 없다.
  - 참조하는 모듈이 왼쪽 열, 참조되는 모듈이 오른쪽 열이다. 의존하는 모듈이 없는 모듈이 맨 오른쪽이다.
  - 실선은 의존이다(`allowedDependencies`). 화살표가 가리키는 모듈을 참조한다. 열을 건너뛰는 선은 사이의 마디를 피해 아래로 휜다.
  - 점선은 이벤트다. 발행하는 모듈에서 수신하는 모듈로 가고 이벤트 이름이 붙는다. 수신하는 모듈은 `listeners[].on`에서 얻는다.
  - 마디에는 모듈 이름과 요약(`화면 4 · 인터페이스 2 · 이벤트 1`)이 있다. 마디는 링크이고 누르면 그 모듈이 선택된다.
  - 모듈을 선택하면 그 모듈에 닿는 선은 짙게, 나머지는 흐리게 보인다. 선의 색은 중립이다.
  - 의존이 순환하면 알림으로 알리고, 순환하는 모듈을 맨 오른쪽 열에 둔다.
- **표**: 행은 참조하는 모듈, 열은 참조되는 모듈이다. 칸에 `의존`과 `이벤트 수신: {이벤트}`가 보인다. 모듈이 많거나 화면 낭독기를 쓸 때 본다.
- **속성**: 왼쪽 열이 항목 이름인 표다.

  | 구획 | 항목 |
  | --- | --- |
  | 앱 (선택한 모듈이 없을 때) | 기본 패키지, 메인 클래스, Cozy 버전, 스타터, 모듈 수, 미구현 항목 수 |
  | 기본 정보 | 모듈, 패키지, 의존 모듈, 참조하는 모듈(이 모듈에 의존하는 모듈), 미구현 항목 수 |
  | 공개 API | 명령 인터페이스와 메서드, 조회 인터페이스와 메서드, DTO, 이벤트(필드, 발행 위치, 수신하는 리스너), 공개 프래그먼트 |
  | 이벤트 리스너 | 리스너와 수신 이벤트 |
  | 화면 | 화면 템플릿. 화면 명세가 있으면 화면 보기로 이어진다 |

- **미구현 항목**: 화면 아래에 앱 전체의 미구현 항목이 `파일:줄`과 채울 내용으로 보인다.

## 코드 생성

생성 항목을 고르고 폼을 채워 **변경 파일 확인**을 누르면 cozy 명령의 계획(`--dry-run`)이 보이고, **적용**을 누르면 같은 명령을 실행한다. 워크벤치가 파일을 쓰는 곳은 여기뿐이고, 쓰는 것은 cozy 명령이다.

- **목록**: 생성 항목은 `group` 순서로 묶이고 `title`과 명령(`cozy add crud`)으로 보인다.
- **폼**: `cozy recipes --json`의 `params`로 그린다. 위치 인자와 옵션은 글자 칸, 고를 값이 있으면 선택 칸, 여러 번 쓰는 옵션(`--field`, `--param`)은 한 줄에 하나씩 적는 칸이다. 모듈 칸은 지금 있는 모듈을 고를 수 있다.
- **명령**: 폼의 값으로 인자 배열을 만든다. 화면에는 터미널에 붙여 넣을 수 있는 글(공백이 있는 인자는 큰따옴표)로 보이고 복사할 수 있다. 셸을 거치지 않는다.
- **변경 파일과 적용 결과**: 파일마다 `생성`·`수정`·`변경 없음`, 미구현 항목(`파일:줄`), 수동 수정 항목(파일, 할 일, 넣을 내용. `add field`가 목록이나 상세의 자리를 찾지 못했을 때), 다음 할 일. 문구는 cozy 명령의 것이다.
- **같은 결과**: 폼으로 적용한 것은 같은 명령을 터미널에서 실행한 것과 글자까지 같다. 다시 적용하면 "변경 사항 없음"이다.
- **거절**: 명령이 거절하면(없는 아이콘, 내용이 다른 파일 등) 이유를 보이고 아무 파일도 바꾸지 않는다. 필수 값이 비면 명령을 부르기 전에 알린다.
- **보이는 때**: 적용한 뒤 "앱을 다시 빌드하고 실행해야 보입니다"를 알린다. 실행 중인 앱은 빌드 결과(`target/classes`)를 읽기 때문이다.

### 쓰는 요청의 조건

| 조건 | 어기면 |
| --- | --- |
| POST이고 CSRF 토큰이 있다 (런타임 기본) | 403 |
| `Origin` 헤더가 있으면 이 앱의 주소와 같다 | 403 |
| 앱 프로젝트 폴더를 찾았다 | 409 |
| `step`이 `plan`이나 `apply`다 | 400 |

- 쓰는 경로는 cozy 명령의 계획이 정한다. 워크벤치는 경로를 입력받지 않는다.
- "샘플 데이터" 탭의 저장과 상태 복제도 같은 조건을 따른다.

## 샘플 데이터 (fixture 편집)

화면의 "샘플 데이터" 탭(`view=fixture`)은 화면 스펙(`src/main/resources/specs/{화면}.yml`)의 상태 하나에 든 값을 모델의 구조대로 보인다. 고쳐서 **저장**하면 스펙 파일의 그 값만 바뀐다. 워크벤치가 직접 쓰는 파일은 스펙 YAML뿐이다. 이 탭을 열면 오른쪽 칸이 넓어진다(21rem → 28rem).

- **구획**: 상태의 모델마다 하나다. 모델 이름과 타입(`result` `ListResult`)이 제목이다. 검증 오류(`_errors`)도 구획 하나다.
- **타입**: 화면 명세의 `model:`이 가리키는 Java 타입을 실행 중인 앱에서 읽는다. record는 구성 요소, 폼 클래스는 setter가 있거나 public인 필드가 속성이다(선언 순서).
- **속성 이름**: 한글 이름을 앞에, 식별자를 뒤에 쓴다(`제목 title`). 한글 이름은 DTO 소스의 Javadoc에서 읽는다(`SourceDocs`). 설명 전체는 이름에 마우스를 올리면 보인다.

  | 타입 | 읽는 곳 | 이름 |
  | --- | --- | --- |
  | record | 타입 Javadoc의 `@param 이름 설명` | 설명의 괄호·쉼표·마침표 앞까지 (`언제 (yyyy-MM-dd HH:mm)` → `언제`) |
  | 폼 클래스 | 필드 바로 위의 Javadoc (`/** 제목 */`) | 같다 |
  | `CozyPage` | 워크벤치가 아는 이름 (소스가 앱에 없다) | 현재 페이지, 페이지 크기, 전체 건수 |

  - 소스는 `src/main/java`에서 타입의 파일(중첩 타입은 바깥 타입의 파일)을 찾는다. Javadoc이 없거나 읽지 못하면 식별자만 보인다.
  - `cozy add crud`는 화면 DTO(`Row`, `ListResult`, `Detail`)의 `@param`과 폼·필터 필드의 Javadoc을 필드 라벨로 쓴다. `cozy add field`는 `@param` 줄이 있는 record에 새 구성 요소의 줄을 더한다([cli.md](cli.md)).
- **객체는 속성 표**다. 왼쪽 열이 속성 이름과 종류, 오른쪽 열이 입력이다. 객체 안의 객체와 목록은 표 아래에 경로(`page`, `memo/bodyLines`)를 제목으로 따로 보인다.
- **객체의 목록은 그리드**다. 열은 원소 타입의 속성, 행은 목록의 항목이다. 스칼라의 목록은 "값" 열 하나다. 목록이 비어도 열은 보인다. 그리드가 칸보다 넓으면 가로로 스크롤한다.
- **입력**: 타입에 맞는 입력을 쓴다.

  | 타입 | 종류 | 입력 |
  | --- | --- | --- |
  | `boolean`, `Boolean` | true/false | 체크박스 |
  | 정수형(`int`, `long`, `Integer`, `BigInteger` …) | 정수 | 숫자 입력(간격 1) |
  | 실수형(`double`, `BigDecimal` …) | 숫자 | 숫자 입력 |
  | `LocalDate` · `LocalDateTime` · `LocalTime` | 날짜 · 날짜와 시각 · 시각 | 날짜·시각 입력 |
  | enum | 타입 이름 | 상수 가운데 고르는 선택 칸 |
  | 그 밖(`String`, `java.*`) | 텍스트 | 글자 칸 |

  - 지금 값이 입력에 맞지 않으면(체크박스 자리의 `yes`, enum에 없는 이름) 글자 칸으로 보인다.
  - `null`인 값은 빈 칸이고 `null`이 흐리게 보인다. 비워 둔 채 저장하면 바뀌지 않는다.
  - 체크박스는 숨은 `false` 뒤에 놓인다. 끄면 `false`, 켜면 `true`가 간다(같은 이름의 마지막 값).
- **타입을 알 수 없으면**(찾을 수 없는 클래스, `Map`, `Object`, `_errors`) YAML의 모양과 값의 종류대로 묶는다. 찾을 수 없는 클래스는 구획에 이유가 보인다. 목록의 열은 항목들의 키를 모은 것이다.
- **없음**: 타입에는 있는데 명세에 없는 값은 "없음"으로 보인다. 그리드 안의 목록과 객체는 요약(`목록 2개`, `객체`)으로 보인다. 둘 다 여기서 고치지 않는다.
- **자리**: 입력의 이름은 `v.` 뒤에 상태 안의 경로(`result/rows/0/title`)다.
- **행 추가·복제·삭제**: 그리드의 행마다 복제와 삭제 버튼, 그리드 아래에 "행 추가" 버튼이 있다. 모두 저장과 같은 폼의 버튼이어서, 적던 값을 먼저 반영하고 행을 고친 뒤 한 번에 저장한다. 저장한 뒤 그 그리드로 돌아온다(`#fixture-result-rows`).
  - **추가**: 원소 타입의 기본값으로 만든 행을 끝에 더한다. 글은 빈 글, 숫자는 0, 참·거짓은 false, 날짜는 오늘, enum은 첫 상수, 목록은 `[]`다. 원소 타입을 모르면 마지막 행을 복제한다. 타입도 행도 없으면 버튼이 꺼진다.
  - **복제**: 그 행의 글을 그대로 바로 아래에 넣는다. **삭제**: 그 행의 줄을 지운다. 마지막 행을 지우면 `[]`가 된다.
  - 블록 목록(`- …`)은 줄 단위로, 흐름 목록(`[a, b]`)은 괄호 안에서 고친다. 블록 맵의 빈 목록(`rows: []`)에 첫 행을 더하면 블록 목록이 된다. 한 줄에 한 행이 아닌 블록 목록은 고치지 않고 이유를 알린다.
  - 바꾼 뒤에도 저장 전 확인(`ScreenSpec.verify`)을 거친다. 기본값이 모델 타입의 검사(예: `CozyPage`의 페이지는 1 이상)에 걸리면 저장하지 않는다.
  - 칸에서 Enter를 누르면 저장이다. 폼의 첫 제출 버튼은 숨은 저장 버튼이다.
- **값만 바꿔 쓴다**: YAML을 다시 쓰지 않고 파서가 알려 주는 값의 자리만 바꾼다. 주석, 키 순서, 들여쓰기, 다른 값은 글자 그대로 남는다.
  - 글은 글로 남는다. `2026`이나 `true`를 글 자리에 적으면 따옴표로 감싼다. 쌍점, 쉼표, 괄호처럼 YAML이 달리 읽을 글자가 있어도 따옴표로 감싼다.
  - 원래 따옴표가 있던 값은 따옴표를 유지한다.
- **저장 전에 확인한다**: 보인 값과 다른 것만 바꾼다(같은 때를 가리키는 날짜와 시각은 같은 값). 바꾼 값이 종류에 맞는지(정수, 날짜, enum 상수 등) 먼저 보고, 바꾼 스펙을 렌더링 검사와 같은 방법으로 읽고(`ScreenSpec.parse`), 모든 상태의 값을 모델 타입으로 바꿔 본다(`ScreenSpec.verify`). 맞지 않으면 이유를 보이고 쓰지 않는다.
- **폼을 연 뒤 파일이 바뀌었으면** 덮어쓰지 않는다. 다시 열어 고친다.
- **바로 보인다**: 워크벤치가 있으면 화면 스펙을 소스 폴더에서 읽는다(`ScreenSpecs` 빈). 저장한 값이 다시 빌드하지 않아도 미리보기와 패턴 카탈로그에 보인다. 소스 폴더의 스펙을 읽지 못하면 빌드된 스펙을 보이고 이유를 알린다.
- **상태 복제**: 지금 상태의 글을 새 이름으로 바로 아래에 넣는다. 이름은 영문으로 시작하고 영문, 숫자, `-`, `_`만 쓴다. 새 상태는 복제한 뒤 값을 고쳐 만든다.
- **고치지 못하는 것**: 여러 줄 값(`|`, `>`)과 비어 있는 값은 읽기 전용이다. 키를 더하고 빼는 일, 그리드 칸 안의 목록과 객체, 상태를 지우는 일은 스펙 파일에서 한다.

| 요청 | 하는 일 |
| --- | --- |
| `POST /cozy/dev/workbench/fixture` (`spec`, `state`, `hash`, `v.{자리}`) | 값을 저장한다 |
| 같은 요청 + `row=add:{목록}`, `row=duplicate:{목록}/{행}`, `row=delete:{목록}/{행}` | 값을 저장하고 행을 고친다. 행은 0부터. 형식이 다르면 400 |
| `POST /cozy/dev/workbench/state` (`spec`, `from`, `name`, `hash`) | 상태를 복제한다 |

- 쓰는 요청의 조건은 "코드 생성"과 같다(CSRF, 같은 Origin, 프로젝트 폴더). 없는 화면이면 404다. 쓰는 파일은 스펙 폴더 바로 아래의 이미 있는 `{화면}.yml`뿐이다.

## 구조 트리

- 원본은 `cozy describe --json`의 `screens[].outline`이다([cli.md](cli.md)). 워크벤치는 같은 프로세스에서 cozy 명령을 부르고 따로 템플릿을 읽지 않는다.
- 줄마다 표시 이름과 식별자가 보인다(`목록 탐색` `list-with-filter`). 종류(레이아웃, 패턴, 컴포넌트, 영역, 프래그먼트)는 속성 표와 줄의 `title`에 있다.
- 안의 줄은 세로 선으로 이어진다. 안에 줄이 있는 줄은 왼쪽 표식을 눌러 접고 편다(`<details>`). 이름을 누르면 접히지 않고 선택된다. 미리보기에서 접힌 줄 안의 요소를 선택하면 다시 펴진다.
- 줄에 마우스를 올리면 미리보기의 해당 요소가 점선으로 표시된다.
- **삽입**(`th:replace`, `th:insert`): 매니페스트에 있는 fragment는 `label`과 식별자로 보인다. `label`이 없거나 매니페스트에 없으면 종류(`컴포넌트`, `프래그먼트`)와 식별자로 보인다.
- **영역**: 삽입이 `~{::#id}`로 넘기는 요소다. 그 삽입의 파라미터 `label`(`필터 영역`)과 파라미터 이름(`cozyFilter`)으로 보인다.
- **프래그먼트 선언**(`th:fragment`)은 `프래그먼트`와 이름으로 보인다.
- 아이콘은 구조가 아니므로 뺀다. 줄마다 `templates/{템플릿}.html:{줄}`이 붙는다.

## 요소에서 소스로

미리보기에서 요소를 누르거나 구조 트리의 이름을 누르면 오른쪽 칸에 그 항목의 속성(소스 위치, 상위 경로 포함)이 보이고, 트리의 해당 줄이 함께 선택된다.

- **요소 선택** 스위치가 켜져 있으면 미리보기의 클릭이 선택이 된다(링크와 버튼이 동작하지 않는다). 끄면 미리보기가 보통 화면처럼 동작한다.
- **위치**: 화면 템플릿의 `src/main/resources/templates/{템플릿}.html:{줄}`이다.
  - 화면 템플릿의 요소면 그 요소의 줄이다.
  - 프레임워크나 다른 모듈의 fragment가 그린 요소면, 화면 템플릿에서 그 fragment를 넣은 줄이다. 실제로 그린 템플릿과 줄은 "렌더링한 템플릿"으로 함께 보인다.
  - 넣은 fragment가 다시 넣은 fragment가 그린 요소(패턴 안의 제목 등)는 가까운 삽입을 고르고 "삽입 위치는 추정"이라고 알린다.
- **경로 복사**는 `파일:줄`을, **에이전트용 복사**는 아래 글을 클립보드에 넣는다. 클립보드를 쓸 수 없으면 글을 펼쳐 골라 둔다.

```text
Screen: memo-list (state: default)
Element: <td class="text-secondary text-nowrap"> "2026-11-06 10:00"
Source: src/main/resources/templates/memo/api/list.html:50
Inside: app-shell (레이아웃) > list-with-filter (패턴) > cozyResult (#result) > result (fragment 선언) > data-table (컴포넌트)
Spec: src/main/resources/specs/memo-list.yml
Playbook: .agents/skills/cozy-helper/references/screens/PLAYBOOK.md
```

- 다른 템플릿이 그린 요소면 `Rendered by: …` 줄이, 추정이면 `Note: …` 줄이 더 붙는다.
- IDE를 띄우지 않는다. 위치를 복사해 IDE의 "파일로 이동"에 붙인다.

### 위치를 싣는 방법

- 워크벤치는 미리보기를 `/cozy/dev/catalog/screen?…&inspect=1`로 부른다. 이 요청에서만 요소마다 `data-cozy-src="{템플릿}:{줄}"`이 붙는다(`SourceLocationDialect`).
- **그 밖의 HTML은 달라지지 않는다.** `inspect`가 없는 미리보기(렌더링 검사가 부르는 것), 앱 화면, 카탈로그의 fragment 미리보기에는 붙지 않는다. `inspect`가 있는 응답도 이 속성을 빼면 없는 응답과 같다.
- **줄 번호 보정**: Thymeleaf는 파서 주석(`<!--/* … */-->`)을 줄바꿈까지 지운 뒤 읽으므로, 여러 줄짜리 파서 주석 뒤의 줄 번호가 당겨진다. 워크벤치가 템플릿 원문으로 실제 줄을 되찾는다(`SourceLines`). 파서 주석과 같은 줄에서 시작하는 요소는 주석 앞에 있다고 본다.
- 감싸는 구조는 `describe`의 `outline`에서 줄이 `line`~`endLine` 안에 드는 마디다.

## 화면 규칙

워크벤치 자신의 화면도 Tabler 구조와 [design.md](design.md)를 따른다. 인라인 스크립트와 스타일이 없고, 보정은 `cozy.css`의 `cozy-workbench-*`에 있다. 스크립트는 `/cozy/workbench.js` 하나이고 워크벤치 화면에서만 읽는다.
