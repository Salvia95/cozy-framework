# 문구와 용어

버튼, 화면 제목, 알림, 빈 상태, 오류 문구를 쓰거나, 화면에 보일 용어와 표시 이름을 정할 때의 기준이다. 원문은 `docs/conventions/design.md` §6, 워크벤치 용어는 `docs/conventions/workbench.md`의 "용어"다.

## 문구의 원칙

- **사용자가 하는 일의 말로 쓴다.** 시스템이 내부에서 하는 일(저장소, 요청, 처리)이 아니라 사용자가 하는 일(만들기, 저장, 삭제)로 쓴다.
- **대상을 밝힌다.** "만들기"가 아니라 "메모 만들기"다. 한 화면에 대상이 여럿일 때 헷갈리지 않는다.
- **같은 일은 같은 말로 쓴다.** 목록 머리의 버튼, 빈 상태의 버튼, 만들기 화면 제목, 만들기 폼의 주 버튼은 모두 "메모 만들기"다.
- **존댓말 평서형(-습니다, -세요)을 쓴다.** 지금 화면의 모든 문장이 이 형태다. 버튼과 제목은 마침표 없는 명사구다.

## 대상별 규칙

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 버튼 | 대상 + 동사. 수정 폼의 주 버튼만 "저장" | 메모 만들기, 저장, 삭제, 조건 지우기 |
| 화면 제목 | 목록은 대상, 만들기·수정은 "대상 + 동사", 상세는 대상 이름 | 메모 / 메모 만들기 / 메모 수정 / 회의록 정리 |
| 결과 알림 | 대상을 + 과거형 | 메모를 만들었습니다, 메모를 수정했습니다, 메모를 삭제했습니다 |
| 변경 없음 | 고정 문구 | 바뀐 내용이 없습니다 |
| 빈 상태 | 무엇이 없는지 + 다음에 할 일 | 메모가 없습니다. 첫 메모를 만들어 보세요. |
| 조건 결과 없음 | 고정 문구(`noResults`) | 조건에 맞는 결과가 없습니다. 검색어나 조건을 바꿔 보세요. |
| 칸 오류 | 무엇을 하면 되는지 | 제목을 입력하세요 |
| 삭제 확인 | 제목 "대상 삭제", 지울 대상 이름, 되돌릴 수 없음 | 메모 삭제 / 지울 메모: 회의록 정리 / 지우면 되돌릴 수 없습니다. |

## 용어의 원칙

- **한 개념에 한 용어다.** 같은 것을 화면마다 다른 말로 부르지 않고, 다른 것을 같은 말로 부르지 않는다. 예전에 "값"이 화면에 따라 샘플 데이터와 DTO를 함께 뜻해서 혼란을 냈다.
- **통용되는 표현을 쓴다.** 동작은 일반 UI 용어(추가, 삭제, 저장, 적용, 확인, 검색, 복사), 개발 용어는 통용 표기(프래그먼트, 컴포넌트, DTO, 이벤트 리스너, 마이그레이션)를 쓴다.
- **새 조어를 만들지 않는다.** "바뀌는 조각", "채울 코드", "부품"처럼 풀어 쓴 말은 사용자가 반려했다.
- **새 용어가 필요하면 용어집에 먼저 넣는다.** 워크벤치는 `workbench.md`의 용어표가 기준이다. 앱 화면은 그 앱의 업무 용어를 따르되 한 앱 안에서 하나로 맞춘다.

## 표시 이름과 식별자

- **사람이 읽는 이름이 앞, 식별자는 뒤다.** 식별자는 소스에서 다시 찾는 데 필요하므로 지우지 않고 고정폭 회색 글자로 붙인다: `페이지네이션 pagination`.
- **이름은 데이터에서 가져온다.** 템플릿에 한글 이름을 직접 적지 않는다.

  | 대상 | 이름의 출처 | 없을 때 |
  | --- | --- | --- |
  | 레이아웃, 패턴, 컴포넌트 | 매니페스트 항목의 `label` | 종류와 식별자 |
  | 패턴이 받는 영역 | 매니페스트 파라미터의 `label` + "영역" | "영역"과 파라미터 이름 |
  | 화면 | 화면 명세의 `title` | 식별자 |
  | 화면 DTO의 속성 | DTO 소스의 Javadoc(record `@param`, 폼 필드 Javadoc) | 식별자 |
  | 상태 | 관례 이름 사전(`default` 기본, `empty` 데이터 없음, `noResults` 검색 결과 없음, `paged` 여러 페이지, `invalid` 입력 오류) | 식별자 |
  | 생성 항목 | `cozy recipes --json`의 `title`, `group` | — |
  | 규칙 | `cozy-rules`의 `RuleNames` | ID만 |
  | 고를 값 | 매니페스트 파라미터의 `choices` 맵(`info: 정보`) | 값 그대로 |

- **프레임워크 컴포넌트의 표시 이름은 범정부 UI/UX 디자인 시스템(KRDS)의 명칭을 따른다.** 같은 역할의 컴포넌트나 기본 패턴이 있으면 그 이름을 쓴다(표, 페이지네이션, 배지, 모달, 토스트, 스피너, 목록 탐색, 입력폼, 상세 정보 확인). 명칭만 따르고 스타일과 마크업은 가져오지 않는다.
- **에이전트에게 넘기는 글은 식별자로 쓴다.** 워크벤치의 "에이전트용 복사"처럼 기계나 에이전트가 읽는 글에는 표시 이름 대신 식별자를 쓴다.
- **cozy 명령의 메시지는 명령이 낸 그대로 보인다.** 워크벤치 화면 용어 규칙을 명령 메시지에 적용하려면 명령과 에이전트 문서를 함께 바꿔야 하므로 따로 결정한다.

## 코드 안의 문구

- 화면 문구에 ADR, PRD, 마일스톤 표기를 쓰지 않는다. 템플릿 주석도 같다. 주석은 그 자체로 맞는 설명이어야 한다.
- fragment 인자로 넘기는 문자열에 작은따옴표와 역슬래시를 쓰지 않는다. Thymeleaf가 읽지 못한다. 큰따옴표와 `&`는 문자 참조로 적는다.
