# 색, 글자, 간격

색, tone, 배지, 글자 크기와 굵기, 간격, 밀도를 정하거나 대비 문제를 고칠 때의 기준이다. 원문은 `docs/conventions/design.md` §4, §5, 토큰은 `cozy-ui/src/main/resources/META-INF/resources/cozy/cozy.css`다.

## 색의 원칙

- **색은 의미에만 쓴다.** 꾸미려고 색을 고르지 않는다. 화면 대부분은 흰색과 회색이다.
- **역할은 셋뿐이다.**

  | 역할 | 색 | 쓰는 곳 |
  | --- | --- | --- |
  | 중립 | 흰색·회색 | 본문 글자, 카드, 보조 글자(`text-secondary`, 5.5:1) |
  | 조작 | 파랑(primary) | 주 버튼, 링크, 현재 메뉴, 현재 페이지 번호, 포커스 |
  | tone | 아래 표 | 상태와 알림만 |

- **분류는 색으로 나누지 않는다.** 종류가 다른 것은 neutral 배지의 글자로 구분한다. 종류마다 다른 색 배지를 쓰면 상태처럼 읽힌다.
- **색만으로 뜻을 전하지 않는다.** 알림에는 아이콘이, 상태 배지에는 글자가 붙는다.
- **숫자 카드(`stat`)와 활동 아이콘은 중립이다.** 의미 없는 primary·azure·green을 고르지 않는다.

## tone

| tone | 뜻 | 글자 / 바탕 | 대비 |
| --- | --- | --- | --- |
| `neutral` | 분류, 보조 정보 (예: 고정) | `#3f3f46` / `#f0f0f2` | 9.2:1 |
| `info` | 알림, 진행 중, 바뀐 내용 없음 | `#0a4f94` / `#e6f0fa` | 7.1:1 |
| `success` | 완료, 정상 | `#1d6b30` / `#e7f5ea` | 5.8:1 |
| `warning` | 주의, 미완료 | `#7a4300` / `#fdf1dc` | 7.1:1 |
| `critical` | 오류, 할 수 없음, 되돌릴 수 없는 동작 | `#a51d1d` / `#fbe9e9` | 6.4:1 |

- tone을 고를 때는 "이것이 사용자에게 무엇을 요구하는가"로 판단한다. 아무것도 요구하지 않으면 neutral이다. 주의를 요구하면 warning, 행동을 막거나 되돌릴 수 없으면 critical이다.
- 토큰은 `cozy.css`의 `--cozy-{tone}-fg`, `--cozy-{tone}-bg`다. 앱은 토큰을 직접 쓰지 않는다.

## 앱 화면에서 색을 쓰는 방법

- 색은 tone을 받는 컴포넌트가 고른다: `badge('고정', 'neutral')`, `alert('critical', …)`, `toast(kind, …)`, `deleteConfirm(…)`, `CozyFlash.warning(…)`.
- 앱 템플릿에서 허용하는 색 관련 클래스는 `text-secondary`, `text-muted`, `btn-primary`뿐이다.
- 금지(R14): `bg-*`, `text-{색}`, `border-{색}`, `link-{색}`, `badge-{색}`, `alert-{색}`, `avatar-{색}`, `btn-{색}`(primary 제외), `btn-outline-*`, `btn-ghost-*`, `status-*`, `ribbon-*`. 식으로 이어 붙인 색 클래스(`|bg-${color}-lt|`)도 확인할 수 없으므로 실패한다.
- 글자로 쓴 tone은 다섯 가지 중 하나여야 한다. `badge('고정', 'blue')`는 실패한다.
- 맞는 컴포넌트가 없어서 색이 필요하다면 앱에서 색을 쓰지 말고, tone을 받는 컴포넌트를 프레임워크에 더할지 따진다(`framework-ui.md`).

## 대비

| 대상 | 기준 (WCAG 2.2 AA) |
| --- | --- |
| 글자 | 4.5:1 이상. 24px 이상이거나 18.66px 이상 굵은 글자는 3:1 이상 |
| 아이콘, 경계선, 포커스 표시 | 3:1 이상 |

- 배경은 겹친 결과(합성된 배경)로 잰다. 선택한 줄, 연한 배지, 비활성처럼 보이는 글자에서 자주 미달한다.
- Tabler 기본값이 미달인 곳은 `cozy.css`에서 바로잡는다. 이미 고친 곳: 보조 회색(`--tblr-secondary` #666, 5.5:1), 알림 글자와 아이콘, 칸 오류 글자(6.3:1), 위험 버튼(`cozy-btn-critical`, `cozy-btn-critical-fill`), 모든 입력의 테두리(`--cozy-control-border` #8c8c8c, 3.4:1), 입력의 포커스 표시(2px primary).
- 입력 보정은 공통 규칙 하나가 모든 화면(앱, 카탈로그, 워크벤치)에 걸린다. 화면이나 영역마다 포커스·테두리를 따로 고치지 않는다(`DesignPrinciplesTest`가 확인한다).
- 새 색 조합을 쓰면 수치를 재서 주석에 남긴다(`cozy.css`의 기존 주석처럼 "9.2:1 분류, 보조 정보").

## 글자

- 글꼴은 Pretendard(벤더 자산)다. 외부 글꼴을 쓰지 않는다.
- 숫자와 날짜는 자릿수를 맞춘다(`body`에 `tabular-nums`가 이미 있다).

| 용도 | 크기 | 요소 |
| --- | --- | --- |
| 화면 제목 | 20px | `.page-title`. 화면에서 가장 큰 글자 |
| 카드 제목 | 16px | `.card-title` |
| 본문, 입력, 버튼 | 14px | 기본 |
| 보조(표 머리, 시각, 설명) | 12~14px, `text-secondary` | 12px보다 작게 쓰지 않는다 |

- 위계는 굵기와 크기로 나눈다. 색만으로 위계를 만들지 않는다.
- 화면 제목보다 큰 글자를 본문에 두지 않는다. 숫자 카드의 값도 화면 제목의 위계를 넘지 않는다.
- 한글은 단어 중간에서 줄을 바꾸지 않는다. 빈 상태와 알림은 `word-break: keep-all`이 이미 걸려 있다. 새 문장 영역을 만들면 같은 처리를 `cozy.css`에 더한다.
- 식별자(모듈 이름, 파일 경로)는 중간에서 끊지 않고 통째로 다음 줄로 넘긴다.

## 간격

4px 단위이고 Tabler 단계를 쓴다. 임의의 px 값을 만들지 않는다.

| 간격 | 값 | 넣는 것 |
| --- | --- | --- |
| 버튼 사이 | 8px | `btn-list` |
| 입력 칸 사이 | 16px | `mb-3` (`field`가 넣는다) |
| 카드 안쪽 | 20px | `card-body` |
| 카드 사이 | 16px | `row-cards` |
| 제목줄과 본문 사이 | Tabler 기본 | `page-body` |

- 카드 안의 내용은 카드 테두리에 닿지 않는다. 카드 안에는 `card-body`, `list-group list-group-flush`, `card-table` 중 하나를 둔다.

## 표

- 열 머리, 행 머리(속성 표의 항목 이름), 행 번호처럼 항목을 나타내는 칸(`th`)은 가운데, 값 칸은 왼쪽이다. `cozy.css`의 `.table th` 하나가 모든 표에 건다. 화면에서 머리 정렬을 따로 고치지 않는다(`DesignPrinciplesTest`가 `th`의 왼쪽·오른쪽 정렬 규칙을 막는다).
- 입력 그리드는 칸 전체가 입력이고 칸의 선이 입력 테두리 토큰으로 그어진다. 포커스는 칸 안쪽 링이다.

## 밀도

- 앱 화면의 밀도는 "보통" 하나뿐이다. 촘촘한 밀도는 두지 않았다. 전환 수단과 두 벌의 검증이 필요하기 때문이다.
- 한 화면 안에서 밀도를 섞지 않는다.
- 워크벤치는 예외로 높은 밀도를 쓴다. 줄 간격만 좁히고 글자 크기(12px 이상)와 대비 기준은 같다(`workbench.md`).

## 확인 방법

- 빌드: R14가 앱 템플릿의 색 클래스와 없는 tone을 잡는다.
- 화면: runtime-verifier의 V9가 보이는 모든 글자의 대비를 합성된 배경으로 재고, 아이콘과 포커스·경계선의 3:1을 본다. 미달이면 글자색, 배경색, 비율, 요소를 함께 보고받는다.
