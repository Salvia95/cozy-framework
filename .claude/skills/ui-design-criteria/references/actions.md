# 버튼과 동작 배치

버튼을 더하거나 옮길 때, 주 버튼·보조 버튼·삭제 버튼·경로 표시의 자리를 정하는 기준이다. 원문은 `docs/conventions/design.md` §1, 빌드 규칙 R15(`docs/conventions/rules.md`)다.

## 왜 이렇게 놓는가

사람의 시선과 조작은 화면의 왼쪽 위에서 시작해 오른쪽 아래에서 끝난다. 읽기를 마친 자리에 다음 동작이 있으면 찾지 않고 누른다. 그래서 무엇을 보고 있는지(제목)는 시작 자리에, 무엇을 할지(주 동작)는 끝 자리에 둔다. 주 동작이 하나여야 사용자가 망설이지 않는다.

## 자리

| 자리 | 무엇을 둔다 | 예 |
| --- | --- | --- |
| 왼쪽 위 | 경로와 화면 제목 | 메모 › 회의록 정리 |
| 오른쪽 위 | 화면 전체에 대한 동작. 주 버튼이 맨 오른쪽 | [메모 만들기] / [삭제] [수정] |
| 본문 | 위에서 아래로 읽는 내용 | 필터 → 표 → 페이지 이동 |
| 오른쪽 아래 | 폼의 끝 동작 | [취소] [메모 만들기] |

## 주 버튼

- **버튼 묶음(`btn-list`) 하나에 주 버튼은 하나다.** 묶음의 맨 오른쪽(마지막)에 둔다. 카드 하나, 모달 하나도 각각 한 영역으로 보고 주 버튼을 하나만 둔다.
- 주 버튼은 `btn-primary`다. 확인 창의 삭제 버튼(`cozy-btn-critical-fill`)도 주 버튼으로 센다.
- 주 버튼이 없는 묶음도 괜찮다. 억지로 주 버튼을 만들지 않는다.
- **표 안에는 주 버튼을 두지 않는다.** 행 단위 동작은 행의 링크로 상세에 간 뒤 상세 머리에서 한다.
- 주 버튼을 비활성화하지 않는다. 누르면 서버가 검증하고 무엇이 모자란지 알린다.
- 버튼 사이 간격은 8px이다(`btn-list`가 넣는다).

## 되돌릴 수 없는 동작

- 삭제처럼 되돌릴 수 없는 동작은 주 자리에 두지 않는다. 상세 머리에 보조 버튼(critical 글자, `cozy-btn-critical`)으로 두고 주 버튼(수정)의 왼쪽에 놓는다: [삭제] [수정].
- 누르면 확인 창이 열린다. 확인 창 안에서는 삭제가 그 창의 주 버튼이고 맨 오른쪽이다: [취소] [삭제].
- 직접 만들지 않고 `deleteConfirm(id, 대상 종류, 대상 이름, 삭제 주소)`를 쓴다. 창의 제목, 본문, 버튼 순서가 그 안에 들어 있다.
- 그 밖의 확인이 필요한 POST 폼은 `data-cozy-confirm="문장"`을 붙인다(`cozy.js`가 제출 전에 묻는다).

## 경로 표시

- 상세, 만들기, 수정 화면은 제목 위에 경로(상위 › 현재)를 보인다. "목록으로" 버튼은 두지 않는다. 경로의 상위 이름이 그 역할을 한다.
- 목록과 개요는 최상위 화면이라 경로가 없다(`null`).
- 수정 화면의 경로는 상위가 대상 이름이다: 회의록 정리 › 메모 수정.

## 버튼의 모양

- 버튼 글자 앞에 아이콘을 둔다(`<svg th:replace="~{cozy/icon/tabler :: icon('plus')}"></svg>메모 만들기`). Tabler가 간격을 맞춘다.
- 자주 쓰는 아이콘: 만들기 `plus`, 수정 `pencil`, 삭제 `trash`, 조건 지우기 `filter-off`, 검색 `search`.
- 아이콘만 있는 버튼에는 `aria-label`을 단다.
- 보조 버튼은 꾸밈 없는 `btn`이다. `btn-outline-*`, `btn-ghost-*` 같은 색 변형을 앱에서 쓰지 않는다.

## 확인 방법

- 빌드: R15가 `btn-list` 안의 동작을 문서 순서로 세어, 주 버튼이 둘 이상이거나 맨 오른쪽이 아니면 실패시킨다. `th:replace`로 끼우는 요소는 무엇이 올지 모르므로 보조 동작 하나로 센다.
- 화면: runtime-verifier의 V10이 영역마다 주 버튼 수와 x 좌표 순서를 잰다. 폼 동작이 오른쪽 아래인지, 삭제가 확인 창을 여는지도 본다.
