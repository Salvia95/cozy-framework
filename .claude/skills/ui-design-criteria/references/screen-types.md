# 화면 유형과 배치

화면을 새로 만들거나 큰 틀을 바꿀 때, 어떤 패턴을 쓰고 본문을 어떻게 나눌지 정하는 기준이다. 원문은 `docs/conventions/design.md` §2, `docs/conventions/ui.md`의 "화면 한 장의 모양"이다.

## 유형부터 고른다

화면의 목적이 유형을 정한다. 목적을 먼저 한 문장으로 적고 아래 표에서 고른다.

| 사용자가 끝내려는 일 | 유형 | 패턴 | 본문 폭 |
| --- | --- | --- | --- |
| 여럿 가운데서 찾고 고른다 | 목록 | `list-with-filter` | `container-xl` |
| 새 대상을 하나 만든다 | 만들기 | `form-page` | 가운데 48rem |
| 대상 하나를 읽고 확인한다 | 상세 | `details` | `container-xl` |
| 대상 하나를 고친다 | 수정 | `form-page` | 가운데 48rem |
| 여러 대상의 현황을 훑어본다 | 개요 | `overview` | `container-xl` |
| 목록을 보면서 고른 항목을 옆에서 바로 읽는다 | 목록 + 상세 | `master-detail` | `container-xl` |
| 일정 간격으로 바뀌는 값을 지켜본다 | 카드 하나 (다른 화면 안) | `polling-panel` | 감싸는 칸 |

- **한 화면에 유형은 하나다.** 상세와 수정 폼을 한 화면에 나란히 두지 않는다. 그 구조가 실제로 버튼 중복 결함을 냈다.
- **목록 + 상세는 읽기용이다.** 오른쪽 상세에서 고치게 하지 않는다. 고치려면 수정 화면으로 간다.
- **워크벤치 화면은 앱 유형을 쓰지 않는다.** 전체 너비 3단의 워크벤치 전용 유형이 따로 있다(`workbench.md`).
- **표에 없는 목적**이면 가장 가까운 유형으로 풀 수 있는지 먼저 본다. 마법사(여러 단계 폼), 촘촘한 표 편집처럼 어느 유형에도 맞지 않으면 새로 만들지 말고 사용자에게 알린 뒤 ADR 개정안을 낸다.

## 화면 틀

모든 앱 화면은 같은 틀 안에 있다. 화면 쪽에서는 틀을 만들지 않고 패턴에 맡긴다.

```text
appShell (왼쪽 세로 내비 + .page-wrapper)
└── <main>
    └── 패턴
        ├── page-header   왼쪽: 경로(있으면) + 화면 제목 / 오른쪽: 동작 버튼 묶음
        └── page-body
            ├── 플래시 (처리 결과, 있을 때만)
            └── 본문 (카드들)
```

- 내비 항목은 `CozyNavItem(이름, 경로, 순서, 아이콘)` 빈으로 등록한다. 요청 경로가 그 경로로 시작하면 활성이다.
- 내비 아래쪽의 앱 메뉴(진단 내보내기, 종료)와 맨 위의 업데이트 배너는 레이아웃이 그린다. 화면이 따로 두지 않는다.
- 레이아웃만 있고 내비가 없는 문서(오류 화면, 카탈로그)는 `base`를 쓴다.

## 유형별 구성

### 목록 (`list-with-filter`)

```text
[제목]                                          [대상 만들기]
┌ 카드 ─────────────────────────────────────────────┐
│ 필터: 검색 칸, 스위치·선택 칸                       │
├──────────────────────────────────────────────────┤
│ 표 (행의 제목이 상세로 가는 링크)                    │
│ 전체 건수 · 페이지 이동                             │
└──────────────────────────────────────────────────┘
```

- 만들기 버튼은 머리 오른쪽의 주 버튼이다. 표 안에 주 버튼을 두지 않는다.
- 필터는 `hx-get`으로 결과 영역만 바꾼다. 결과가 비면 `emptyStateAction` 또는 `noResults`를 그린다(`states-and-feedback.md`).
- 기준 예시에서 행에서 상세로 가는 링크는 제목 칸 하나다(`text-reset fw-medium`).
- 상태 칸, 시각 칸처럼 짧은 칸은 `w-1`과 `text-nowrap`으로 좁힌다.

### 만들기와 수정 (`form-page`)

```text
        상위 › 대상 만들기
        [대상 만들기]
        ┌ <form class="card"> ───────────────┐
        │ 입력 칸 (위에서 아래로 한 열)          │
        ├────────────────────────────────────┤
        │                    [취소] [주 버튼] │
        └────────────────────────────────────┘
```

- 폭은 가운데 48rem이고, 머리와 폼 카드의 왼쪽 끝이 맞는다. 패턴이 `cozy-width-form`으로 맞춘다.
- 입력 칸은 한 열로 위에서 아래로 쌓는다. 칸 사이는 16px(`mb-3`, `field`가 넣는다).
- 수정 화면의 경로는 "대상 이름 › 대상 수정", 주 버튼은 "저장"이다. 만들기 화면의 입력 칸 조각을 같이 쓴다(모듈의 `internal/` 조각).
- 머리 오른쪽에는 버튼을 두지 않는다. 폼의 동작은 폼 카드 아래 오른쪽에만 있다.

### 상세 (`details`)

```text
상위 › 대상 이름                                [삭제] [수정]
┌ 본문 (col-lg-8) ───────────────┐ ┌ 정보 (col-lg-4) ─┐
│ 대상의 내용                      │ │ datagrid: 상태,   │
│                                 │ │ 만든 시각, …      │
└─────────────────────────────────┘ └──────────────────┘
```

- 읽기 전용이다. 머리 오른쪽에 [삭제] [수정] 순서로 두고, 수정이 주 버튼이다.
- 넓은 칸 8에는 사람이 읽는 내용, 옆 칸 4에는 속성(`datagrid`의 이름·값 쌍)을 둔다.
- 기준 예시는 값이 비어 있으면 빈칸으로 두지 않고 `text-secondary` 문장으로 알린다("본문이 없습니다.", "고정 안 함").

### 개요 (`overview`)

```text
[제목]                                          [주 동작 (있으면)]
┌ 숫자 ┐ ┌ 숫자 ┐ ┌ 숫자 ┐ ┌ 숫자 ┐      ← row row-deck row-cards + stat
└──────┘ └──────┘ └──────┘ └──────┘
┌ 카드 ──────────────┐ ┌ 카드 ──────────────┐   ← 본문 카드들
└────────────────────┘ └────────────────────┘
```

- 숫자 카드 줄 다음에 카드들이 온다. 숫자 카드에는 색을 입히지 않는다.
- 다른 모듈의 요약은 그 모듈의 `spi/` fragment로 받는다. 주기 갱신이 필요한 카드는 `polling-panel`로 감싼다.

### 목록 + 상세 (`master-detail`)

- 왼쪽 4칸에 목록(`list-group list-group-flush`), 오른쪽 8칸에 상세(`id="detail"`)다.
- 목록의 링크는 `hx-get`으로 `#detail`만 바꾼다.

## 그리드와 폭의 규칙

- 본문은 Tabler 12칸 그리드 위에서 가운데 정렬한다. 1920px 화면에서 본문 좌우 여백은 같아야 한다(±2px).
- 화면 제목의 왼쪽 끝과 첫 카드의 왼쪽 끝이 맞는다.
- 카드 사이는 16px(`row row-cards`)이고 카드 안쪽은 Tabler 기본(20px)이다.
- 좁은 화면(390px)에서 칸은 위아래로 쌓인다. 가로 스크롤이 생기면 결함이다. 넓은 표는 카드 안에서만 가로로 스크롤한다.
- 패턴이 정한 폭을 화면에서 바꾸지 않는다. 폭이 맞지 않는다고 느껴지면 유형을 잘못 고른 것인지 먼저 본다.

## 패턴에 영역을 넘기는 방법

- 패턴은 영역을 fragment로 받는다. 같은 파일 안의 id나 class로 고른다(`~{::#memo-actions}`, `~{::.memo-row}`).
- 넘길 것이 없으면 `~{}`를 넘긴다(버튼이 없는 머리, 숫자 카드가 없는 개요).
- 경로가 없는 화면은 상위 이름과 상위 주소에 `null`을 넘긴다.
- 시그니처는 `components.md`에 있다.
